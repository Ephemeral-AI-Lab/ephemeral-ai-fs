# Frozen structural content graph experiment

Date: 2026-09-10. All 157 original sealed manifests; all 75,398 authenticated SmallContent identities and all 75,929 Git blob identities. Source attribution is the prior complete authenticated inventory. Read source Git with cat-file, verify every raw Git SHA1, preserve source files.

Four complete graph trials, fixed before encoding: (1) forward-small: first-appearance order, nearest already-selected same-path historical content that fits 8 edges/512KiB canonical/256KiB encoded, plus original physical base if already selected and eligible; (2) reverse-small: latest-appearance reverse order with corresponding future same-path versions, same bounds; (3) git-small: Git actual base DAG, only same SmallContent population, max50 edges/64MiB canonical/64MiB encoded, out-of-population base becomes FULL; (4) git-all: same actual Git DAG over all75,929 blobs, same extended bounds and whole-file representation including large versions. Every trial compares complete FULL cost against candidate prefix +32-byte reference; all FULL resets and descendants counted once. No best-of-independent-target subtraction.

Pinned zstd1.5.7 level3, window18 for SmallContent and window20 for large blobs, content size/checksum on, dictionary ID/workers off. These match existing requested SmallContent parameters; dynamic allocation diagnostic does not prove runtime memory budget. No new matcher. Git graph trials isolate direction/base graph using existing prefix codec, not Git delta instructions. Fixed scope includes losing/no-candidate outputs. Large git-all representation is a separate diagnostic, cannot replace native packs without file-root changes.

Save every selected record in SQLite keyed by original canonical SmallContent ID (all mode records have GitOID too), including target length, selected base, frame, computed depth/canonical/encoded closure. Exported records support compatible SmallContent replacement. Reconstruct every selected graph from the saved records using a bounded64MiB LRU, verify Git identity and original canonical BLAKE3 for all SmallContent objects; no read oracle or production qualification implied by content-only checks. Full157 fixture content membership follows identical authenticated content identities; unchanged metadata still requires parent combined full157 oracle verification.

Report encoded frame bytes, compact record+directory bytes (5B/object +32B/delta), pack headers separately, native unchanged for small-only candidates. SQLite diagnostic file allocation is experiment-container storage, not LayerFS Store storage. Record elapsed time and max graph costs; physical replacement and actual index accounting belong to the combined-copy experiment.
