# CDC overlap-hint experiment: reject extension

The fixed twelve expensive current lockfile records shrink only **144,549 →143,947 bytes**, saving **602 bytes** across three targets (291,222,89 bytes). Eleven eligible alternative trials deliver this saving; no249-record family extension is justified by this sample.

Every original lockfile was checked against its sealed fixture SHA256. The cached product FastCdc scanner reconstructed exact chunk spans; canonical BLAKE3 identities matched selected Store objects, and first appearance matched recorded physical admission pack ranges. Every selected PREFIX base matched the first reconstructed same-offset overlap hint. All twelve actual selected frames were reproduced **byte-for-byte** with Zstd1.5.7, a static1MiB encoder, and exact native setters. All newly encoded alternatives were decoded to identical target bytes. Store SHA256 remained713e43e4f31a489c8eb347b953702ca97c33b17832fbdc0633018584308507f4.

Ten sampled records are already PREFIX, two FULL. Most alternate overlap chunks are no better than the first. The two FULL targets each have a depth-four first predecessor, making a fifth edge ineligible; their second overlap candidates also have depth four. Existing caps therefore explain these FULLs structurally, whereas the expensive existing PREFIX records are mainly poorly compressed by all tested local overlap candidates. This is sample diagnosis, not an attribution of the entire878,925-byte Git mismatch.

There are27 total hint candidates,15 beyond first hints.21 candidates are encoded,2 are rejected after decoding because of depth, and4 are rejected by the prospective cumulative eight-lookup target envelope. Consumed complete closures total57 lookups,343,549 encoded-work bytes and1,472,182 decoded-work bytes across twelve targets. Largest examined raw base closure106,837B.21 candidate compress calls totaled4,113,164ns; candidate decode+auth diagnostics totaled29,936,713ns, including examination needed to classify candidates. These are Python/ctypes diagnostic timings, not public Commit latency or resident-memory measurements.

The experiment enforces existing depth/raw closure and conservative cumulative per-target byte/lookup limits. Original remaining batch512-trial/8MiB quotas were not recorded per sampled object, so integration availability cannot be guaranteed. The simulator can inspect an excluded candidate's full closure to classify it; a foreground implementation would stop reading when its quota is exhausted. The decoder here uses Zstd's dynamic DCtx/refPrefix API for authenticated diagnostic reconstruction; encoder memory is statically bounded, but no equivalence to product decoder allocation or peak RSS is claimed.

Costs are complete records (FULL5+frame; PREFIX37+frame), including base references. Existing physical bases are counted once and retained unchanged. No pack/index/page savings, new selected family graph or whole-Store result is claimed.

`protocol.md` froze selection before trials. `sample.json` contains the twelve IDs, spans and actual hint provenance. `experiment.py` is runnable with executable assertions; `result.json` contains raw costs/timings. `experiment-initial.py`/`result-initial.json` preserve the initial accounting version; the final version charges a decoded depth-ineligible first hint before considering subsequent hints. This accounting correction leaves602B savings unchanged.
