## Evidence and choice

The original FULL population contains 6,143,990 frame bytes whose new pathname
has a unique same-basename removed small file in the preceding selected state.
After subtracting targets already converted by the selected-FULL cache, the
original-frame coverage is 3,660,297 bytes with surviving old parents and
2,193,441 with removed parents. These figures describe candidates, not savings.
They justify inspecting direct removed bindings and bounded removed subtrees.
The existing matcher beat Git COPY/INSERT on four of five identical-base pairs;
retain it and select one base using existing frozen namespace facts.

## Selection and ownership

Build one operation-local sorted basename/content-root catalogue during
StableFileInputs task planning. Resolve removed bindings from dirty directory
overlays against their immutable base directory, with existing batched directory
and inode readers. For a removed directory, enumerate only that removed subtree
iteratively with bounded pages. Do not scan the entire namespace, other historical
snapshots, or file payloads. Genuine inode and same-path predecessors retain
priority. Only a new nonempty regular target strictly below 131072 bytes with
no genuine regular predecessor may receive an optional removed-name hint.
Choose a unique distinct content root for its basename; deduplicate equal roots,
skip ambiguous names. No path-specific fixture heuristic or multiple-base trials.

Inspect at most 16,384 dirty nodes and 32,768 directory-change entries; resolve
at most 4,096 removed bindings/subtree entries, visit at most 4,096 directories,
and traverse at most 64 directory edges. Cap the combined optional directory
lookup, directory page and inode-batch API calls at 8,192; each call retains its
existing bounded authenticated tree/wave implementation. This is a coarse work
cap, not a claim of 8,192 physical object reads or a decoded-byte measurement.
Catalogue and traversal queue together
must own at most 1 MiB, including actual vector/string capacities. Reuse existing
bounded authenticated lookup waves and planning scratch. Enable discovery only
when the existing final-delta planning allowance is at least 4 MiB. Abandon the
whole optional catalogue on a discovery work/memory cap, preserving uniqueness
semantics; integrity/I/O failures remain errors. Any additional metadata-work
guard and exact ownership accounting must be recorded before candidate execution.
Drop the catalogue and traversal scratch when planning ends, before file
producers, reconstruction or compression. No budget or hidden heap fallback is
added. The existing predecessor-bearing plan may use one producer; report that
public speed consequence rather than changing concurrency to hide it.

Carry only the selected root in the existing physical-hint task slot. Never
replace the real before inode record: namespace identity, equality, metadata,
links, modes and publication outcomes remain authoritative and unchanged.

## Reader, format and lifetime

This selection policy runs only for schema 9. Supported older opens do not
promote or change their writer policy. There is no new canonical identity or
persisted record interpretation: existing kind 2 already names a bounded
SmallContent base. Its role is now explicitly permitted to be an already-retained
removed-path candidate. CDC roots remain ineligible; no copied FULL base is
created. The existing selected-FULL session cache remains the fallback when
the physical hint is ineligible, under its unchanged one-candidate policy.

The shared admission reader authenticates the chosen base and every dependency
under the existing maximum 8 edges, 512 KiB total decoded canonical closure
including target, and 256 KiB retained encoded capacity. Existing 2 MiB active
reconstruction and 3 MiB encoding ownership, static codec storage and buffer
lifetimes remain unchanged. Decoder ownership ends before encoder allocation.
Prepare FULL once and at most one eligible DELTA; compare complete record cost
including the base reference, and choose FULL on ties. Retain real physical
bases once, with existing transitive dependency retention; no duplicate base,
unreclaimed-byte subtraction or maintenance outside public timers.

Immutable base-snapshot objects already belong to the operation's Store.
Missing/corrupt dependencies remain integrity failures. Ineligible optional hints
fall back normally. Existing session publication, exact CAS, rollback and private
spool cleanup remain the owners; catalogue state cannot survive planning/rollback.
Old-binary rollback still requires a pre-schema-9 backup, as already documented.

## Implemented ownership before first measurement

The implementation reserves entry and directory vectors once, each for 4,096
elements, and refuses growth. Its catalogue/queue accounting is actual entry
vector capacity times `size_of<(Vec<u8>, ObjectId)>`, directory vector capacity
times `size_of<(DirectoryStateRoot, usize)>`, plus every retained name's actual
capacity, capped at 1 MiB. On arm64 the two fixed arrays total 393,216 bytes.
Names are validated canonical basenames, at most 255 bytes. Sorting is in-place;
equal name/root pairs are deduplicated and differing roots remain ambiguous.
There is no retained pathname or payload array. The traversal queue is dropped
before task planning consumes the catalogue, and the catalogue drops before
producers. Existing planning waves retain the `io_bytes / 16384`, 1..128 limit,
at most 2 MiB of the existing directory-wave allowance at its largest setting,
plus bounded key/inode/page and journal scratch within the 4-MiB eligibility
floor. SnapshotReader's preexisting cache retains its separate existing owner.

One focused workspace test passed before measurement: direct/removed-subtree
discovery, ambiguous/absent names, low-budget and dirty-frontier refusal, exact
physical hint with no fabricated before inode, moved-and-edited Commit, mode,
and historical original bytes. This does not exhaustively qualify old schemas,
POSIX operations or failure injection; the schema-9 capability check delegates
to the unchanged Store format predicate. No decoder or CAS comparison changed.
