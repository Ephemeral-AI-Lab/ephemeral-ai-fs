# Namespace pseudorandom on/off option (#111)

Implemented in commit `72223a499` following the owner's explicit choice: disabling pseudorandom produces generated structured text with identical file paths, classes and sizes. The default remains the original pseudorandom content. This is a benchmark fixture change only; the product/storage policy is unchanged.

## Usage

```bash
bash benchmark/fs-bench-pro/families/init_namespace/perf.sh \
  --case namespace-100-compact-v3 --seed 1 \
  --image layerfs-bench-infra:00f158e9e0a807e5 \
  --perf-fast --pseudorandom

bash benchmark/fs-bench-pro/families/init_namespace/perf.sh \
  --case namespace-100-compact-v3 --seed 1 \
  --image layerfs-bench-infra:00f158e9e0a807e5 \
  --perf-fast --no-pseudorandom
```

The flag is also accepted by the shared setup/preparation and verifier parsers. It requires an explicit `init_namespace` case; other families and contradictory enabled/text selections fail. Without either flag, existing cases remain unchanged. Text mode resolves to `<base-case>-text-v1`, e.g. `namespace-100-compact-v3-text-v1`, with its own fixture profile/digest, cache key and input/proof identity. Explicit text IDs also work. The four new variants are opt-in and do not expand the default four-case mandatory registry. Both on/off still use ordinary public `Client::initialize_layerstack`, identical file-size-based small FULL/DELTA versus large CDC/CAS dispatch, schema10 compression/packing, and no compaction.

Structured text v1 streams ASCII records with file identity, raw size, an incrementing record number and repeated initialization/status fields. Chunk boundaries do not change bytes. It preserves the base file-size/path permutation and metadata. It is deliberately repetitive synthetic text, **not a real repository or a production compression forecast**. Content and CDC boundaries may differ across modes; original random-data acceptance gates cannot be satisfied by the text variant.
