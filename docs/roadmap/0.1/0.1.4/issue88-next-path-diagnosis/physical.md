## S2 is a policy package, not a matcher replacement

The existing product counts and source expose two missing bridges:

1. **Candidate availability.** Public hints are built before CAS filtering at `objects.rs:2046–2073`; each cursor metadata grant consumes131,136 bytes under a shared16MiB operation allowance. Authoritative CAS selection happens later at `objects.rs:3019–3026`. The original run offered hints to only8,468 payload targets, versus58,323 offline prefix trials. S2's extractor supplies a first-overlapping same-path prior from complete frozen source history in deterministic path order. It does not reproduce the public reservation/cursor/producer ordering or first-occurrence ownership. Native compression cannot encode against a prior the public path never supplies. In the S1 prototype eligibility counters additionally include inode leaves, so subtracting its aggregate from the old payload-only denominator is invalid. Structural-origin leaves deliberately have no file first_span: a missing-span diagnostic must gate on the exact payload role and predecessor context, or it will falsely label valid S1 objects as handoff defects. Keep separate structural and payload eligible counts/bytes.

2. **Encoding/read policy.** Current product A is Zstd1 over complete canonical record groups, maximum windowLog16 (`pack.rs:637–675`). B substitutes custom COPY/INSERT programs and must save max(64B,12.5%) at the group level (`pack.rs:410–428`). S2 uses independent raw-chunk Zstd3 frames, windowLog20, implicit canonical framing, actual selected prior instead of FULL-anchor substitution, depth4,1MiB cumulative raw closure, and any strict frame+base-ID saving. Its141MB difference cannot be described as the isolated value of Zstd's matcher or depth4.

Current content metadata values also include five payload objects outside S2's regular-file-only86,412 population. A production integration must retain those objects and preserve their use/role authentication, not silently align totals by dropping them.

## Smallest later integration boundary

The canonical chunk abstraction can stay: maximum32,768 payload bytes and deterministic21-byte canonical framing. The existing ObjectId should remain the key, and every reconstructed raw chunk should be re-encoded/authenticated directly against that canonical ObjectId. The offline screen used raw SHA256/extractor seal equivalence; a product reader should execute its normal canonical identity check.

The smallest honest physical seam is **one explicit versioned native-prefix record plus its bounded reader and writer support**, while leaving namespace, inode, FileState, extent and CDC algorithms intact. It is not a one-line change to the existing zstandard::compress function:

- `pack.rs:44–46` only accepts pack wire1. `pack.rs:108–133` accepts FULL kind0 and custom DELTA kind1 with an instruction count/program. A native prefix frame cannot masquerade as the existing kind1; it needs a declared physical version/record variant and old/new reader compatibility. Old Stores remain read-only compatible through the old decoder; older binaries must reject newly written representation cleanly. No silent in-place schema/format conversion.
- `read.rs:218–284` returns an older FULL anchor for DELTA predecessor hints. `read.rs:516–518` rejects any non-FULL base in ordinary delta waves. S2's actual prior may itself be encoded, so using the current reader unchanged would either reject it or change S2's base policy.
- The versioned reader must walk a bounded single-base closure, detect cycles/missing bases before trust, authenticate every reconstructed base/target, and preserve dependency ownership through publication. The offline algorithm at `content_screen.py:164–198` is a useful executable specification, not a product subsystem to copy wholesale. Existing page/group reads can fetch unrelated records, so sum-of-payload-lengths is not a complete public read-work charge.
- Depth4 on32KiB chunks has an intrinsic maximum163,840 raw closure bytes; this explains the S2 observed maximum. The1MiB S2 ceiling never becomes the active limit for that unit/depth combination. Product bounds must additionally charge all enclosing group decodes, encoded reads, resident prefix/target buffers, pending requests, and codec contexts. `read.rs:382–405` batches requests under an existing1MiB validation reservation; `admission.rs:160–184` already partitions2MiB physical scratch. Blindly adding1MiB per pending target would violate that ownership model.
- The observed S2 encoder context541,720B and decoder123,336B are promising measurements, but not proofs that every static-workspace parameter/input fits. Current product uses non-growing static contexts; offline ctypes uses allocated reusable contexts. Enforce declared static/memory bounds and preserve fallback on optional resource exhaustion rather than assuming offline process RSS proves the library cannot allocate more.
- The installed pinned zstd.h:1124–1143 and1182–1198 documents prefix reference lifetime: the exact prefix must remain unmodified/alive through the next frame; encoder and decoder must use the same prefix, and it is single-use. Reset/rebind for each record, validate one complete frame and expected size/checksum/window, and keep the prefix alive through the call. This is verified primary API documentation, not an inferred cache behavior.

Keeping existing outer group compression around already compressed prefix frames may change the measured S2 advantage and consume extra codec work. Conversely switching all payloads to independent frames changes grouping/framing. Freeze that choice as an explicit physical treatment and compare complete identical populations; do not inherit102MB as its forecast.

No global similarity index, whole-file identity migration, or unlimited cache is required for this boundary. But a reliable native record reader, actual-prior ownership and coverage are required; omitting them would make the prototype small by changing the experiment.

## Exactly one immediate next step

**Finish the already designed unchanged-policy, byte-weighted public correspondence/handoff diagnostic.** Keep budgets, actual cursor decisions, grouping, codec, depth-one anchor policy and producer route unchanged. Attach the reviewed reason/grant tags and project them through the existing CAS owner into unique initially missing targets. Measure first/inherited operation-limit causes, grants triggered by eventually reused/duplicate/missing occurrences, completed no-overlap, missing required spans and actual available prior coverage, with counts AND canonical bytes. Preserve the distinction between shared cursor benefit and avoidable work.

This is the least expensive remaining falsifier before a native-prefix product rewrite. Its hypothesis is that public coverage starvation accounts for a material fraction of the predecessor-present/no-hint byte population. It is contradicted or materially weakened if complete no-overlap/unavailable predecessors dominate instead, if the expected byte cohort is small, or if the unique-target/ownership gates fail. Existing source-derived tail-growth bounds provide a cross-check, not a compression-savings claim.

Only after this bridge is trustworthy should a separately frozen native-prefix physical prototype proceed through format/cycle/resource/identity tests and the approved smokes. Its control is the actual current public policy; any changed codec/grouping/base/depth/coverage package must be named. The current empirical data favors that direction over whole-file conversion, but it does not justify skipping the coverage question or promising134MB.
