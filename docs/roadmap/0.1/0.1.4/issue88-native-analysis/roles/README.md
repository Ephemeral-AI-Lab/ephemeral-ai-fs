# Additive native-aware census

This standalone analysis crate copies the previously validated issue87 role/reference inventory and adds version2 dispatch. The old source, binary, output and manifests remain untouched. It source-includes the measured candidate's exact `objects/pack.rs`; its grammar, Zstandard codec, COPY/INSERT application and the existing content canonical/reference decoders are not reimplemented. No StoreDb connection or product API is added: the evidence connection uses `mode=ro&immutable=1` and never opens through the product READ_WRITE constructor.

Parent must grant the serialized build/census slot and record source/binary/dependency seals, input hash, quiescence, snapshot phase, original acknowledgement allocation and separate output custody before execution. This tool does not authenticate its own supplied path or reconstruct acknowledgement allocation. It refuses to overwrite `roles-inventory.sqlite`. An assertion/error aborts the inventory; a partial output is invalid and must be preserved as such, never reported as zero. No execution has been authorized by this README.

Command shape: `issue88-native-roles DATABASE NEW_OUTPUT_DIRECTORY`. One ascending pack pass writes one spillable SQLite analysis inventory. Pack BLOB size is bounded before copying it. A32MiB FIFO decoded-group cache supports needed older-base reads; no all-payload cache or raw payload files are created. Native frames are independently decoded as needed through at most four prior-pack PREFIX edges. Base reads may revisit records and are census observer work, not product read performance. Every physical record is reconstructed and identified, then matched to the selected locator; every selected base is canonical-authenticated, exact-chunk validated and strictly earlier-pack checked. Legacy DELTA still requires legacy FULL. Native chain glue calls only the product native parser/static decoder and existing canonical chunk encoder.

Whole packs prove contiguous directory coverage and exact EOF. Native groups validate all end offsets once, then parse every fixed header and decode every physical record; demanded product point-read scope remains different. All selected counts and canonical bytes reconcile to SQL selected rows. Any missing selected locator in logical/dependency closure fails. Graph union uses existing canonical reference edges plus layers/commits/workspace-stage roots. `required_objects` includes intermediate physical PREFIX objects, not merely terminal FULL anchors.

## Schema and nested accounts

Existing `records`, `edges`, `roots`, `groups`, `packs` retain their original column layouts. `records.kind` additionally uses `NATIVE_FULL` and `NATIVE_PREFIX`. Never send these rows through a legacy-only FULL/DELTA summary without updating the summary. Each integer byte field is exact for this input logical snapshot; counts/offsets are integers; parsed physical lengths are measured, reconstructed canonical lengths and graph memberships are derived/authenticated. Locators are selected-snapshot locations, not inferred admission timestamps. Unknown temporal provenance stays null in downstream reports.

- `pack_versions(pack,version)`: one row per physical pack; version1/2 selects grammar. `packs.bytes` includes its16-byte header,16-byte entries and all groups.
- `native_records(pack,grp,rec,raw_bytes,frame_bytes,header_bytes,prefix_edges,closure_raw_bytes,base_kind)`: one row per physical native record, including unselected records. `raw_bytes` is reconstructed target payload, separate from physical bytes. `frame_bytes` is stored Zstandard bytes; `header_bytes` is5/37 and already includes the PREFIX32-byte base ID. `prefix_edges` and `closure_raw_bytes` include the demanded target and every required base; FULL has depth0. `base_kind` is the selected immediate base representation or null for native FULL (not applicable).
- `native_groups(pack,grp,full_header_bytes,full_frame_bytes,prefix_header_bytes,prefix_frame_bytes,canonical_bytes)`: exact physical sums of the four native components plus a separate reconstructed canonical dimension. Original `groups.full_bytes/delta_bytes/copy_bytes/insert_frame_bytes/literal_bytes/delta_header_bytes` remain **legacy-only**. Native frame bytes are never mislabeled COPY instructions or INSERT literals.
- Every group satisfies `decoded = 4 + 4*records + legacy_FULL + legacy_DELTA + native_FULL_headers + native_FULL_frames + native_PREFIX_headers + native_PREFIX_frames`. Native groups are RAW, so their encoded length equals this decoded framing length. Reconstructed canonical bytes are not another physical addend. Every legacy DELTA additionally conserves header+COPY+INSERT framing+literals.
- `logical_retained` is logical graph union L; `required_objects` is R=L plus transitive selected physical dependencies. `physical_base_only`, `selected_outside_required`, `physical_unselected` are disjoint questions, not automatic garbage candidates. `physical_base_only` includes intermediate native PREFIX nodes as well as FULL anchors. Report them grouped by representation and exclusive canonical role; shared compressed groups prevent assigning reclaimable bytes from canonical totals.
- `dependency_edges` includes every physical record's immediate dependency plus selected-base representation/role/location and canonical bytes. `selected` distinguishes logically selected sources from physical residue. `dependency_fan_in` separates all physical reference count from selected reference count. Cross-pack/group relationships can be derived directly; canonical size is not compressed attribution.
- `file_content_objects` starts only from authenticated inode-record **content** edges whose target decodes exactly as FileState, then traverses that graph. `file_payload` excludes metadata-value-only FileStates. This is final retained-use classification, not first admission provenance; roots and per-ack pack intervals must establish any historical cohort. Shared file/metadata use does not duplicate exclusive payload roles.

The final report must also reconcile these pack totals to the separate SQLite page/accounting census and original acknowledged allocation. This logical scanner supplies neither allocation equivalence for copies nor historical fragmentation. A source-included codec proves exact wire interpretation, not an independently measured public CPU/read/cache profile.
